# TASK L1: Base auto-collect fails closed AND heals itself

Commit message: `base: collect pass signs before recording, settles every entry by nonce and receipt, validates state strictly`.

## Goal
Collection must never need a manual `state.json` edit. Every transaction the pass can broadcast is signed first and recorded (hash and nonce) on disk before it is broadcast; every recorded entry is settled at the next run start from the chain (receipt, or by nonce); anything that cannot be proven keeps the conservative worst case; bad state fails closed with a one-line message, never a stack.

## Scope
IN: `collector-base.js`, `collector-base-logic.js`, `README.md` (Auto-collect on Base section only), tests, additive handlers in `test/fixtures/mock-chain.js` (`broadcastTransaction`, `getTransactionCount` "latest" vs "pending"). OUT: `settings.js`, `settings.base.example.json` (no new settings keys), `server.js`, the Base server, `run-collector.sh` and every file in G7, the shipped `collect:false`.

## Existing code to reuse
`runPass`, `settledWei`, `spentWindowWei`, `readState`/`serializeState`/`writeFileAtomic`/`initStateFile`, `assertSignable`, `l1Allowance`, `withTimeout`, `isTimeout`/`isRevertClass`, the REFETCH loop, and the test helpers `scene()/fakeSigner()/pass()`.

## Constraints
No new dependency, no network in tests. The static scan of `collector-base.js` for `swap|exactInput|approve(|setApprovalForAll|transfer|safeTransfer|decreaseLiquidity|burn|withdraw|deposit|exactOutput|Router|Quoter` (comments included) keeps passing: do not write the word "transfer" or the others in code or comments. `MANAGER_ABI` stays 3 functions, `ORACLE_ABI` 1. Only `signTransaction` + `broadcastTransaction` carry a transaction out. Each refusal is ONE log line; where the run stops, `result.aborted = true` (exit code 1 through the existing path).

## Design (implementer follows; deviations need the orchestrator)

**L1-1 Sign first, record, then broadcast.** `txFields` gets an explicit `nonce` = the `getTransactionCount(operator,"pending")` value already read for the L1 quote (so the quoted unsigned bytes equal the signed ones). Order per send: `assertSignable` (incl. nonce and exact manager, see below) -> `raw = await signer.signTransaction(txFields)` -> parse with `ethers.Transaction.from(raw)` and require `from == operator`, `to == manager`, and `nonce`, `gasLimit`, `maxFeePerGas`, `maxPriorityFeePerGas`, `value 0n`, `data`, `chainId`, type 2 all equal to what was asked (mismatch: nothing recorded, nothing broadcast, one log line, skip this position, continue) -> `hash` = the hash of that parse (never taken from an RPC) -> reserve: push `{ t, wei: worstCase, kind: "reserved", tx: hash, nonce, from: operator, to: manager, gasLimit, maxFeePerGas, l1 }` and save atomically; if that save fails: log `STOP`, `aborted = true`, NO broadcast, no later send -> `provider.broadcastTransaction(raw)`. The pass uses `signer.address` + `signer.signTransaction` only. Every entry written by this version has `tx` and `nonce`.
- Broadcast throws (any error): the entry stays `reserved` on disk (the broadcast may have reached the network), the send counts toward `maxCollectsPerRun`, `aborted = true`, the run stops cleanly with one log line. It is settled at the next run start (L1-2).
- Broadcast returns nothing, a response without `hash`, or a different hash: set the entry to `kind:"unknown"` at worst case (keep the locally computed `tx`), save, log `STOP: broadcast returned no/mismatching hash`, `aborted = true`, stop. No TypeError.
- After a good broadcast the existing wait/settle/timeout/revert/refetch logic is kept. EVERY `persist(...)` after the reservation (hash, unknown, settlement) that fails sets `aborted = true`, logs `STOP: the budget cannot be recorded`, and leaves the whole loop before any further send.

**L1-2 Run-start settlement (collect mode, state readable).** Wrap the whole phase so no value from state or RPC can throw out of it. For every entry with `kind` `reserved` or `unknown` (any age):
1. Look up `provider.getTransactionReceipt(entry.tx)` (entries with a hash) and `nonceUsed = (await provider.getTransactionCount(operator, "latest")) > entry.nonce` (entries with a nonce).
2. A receipt is ACCEPTED only if: its hash (`hash` or `transactionHash`) equals `entry.tx` (case-insensitive); `from` equals the operator and equals `entry.from` when present; `to` equals `entry.to` when present AND is in `ALLOWED_MANAGERS`; `blockNumber`/`blockHash` present; `gasUsed` is a bigint (or integer string) with `21000n <= gasUsed <= BigInt(entry.gasLimit)`. Accepted: `settledWei` (price clamped to `[0, entry.maxFeePerGas]`, result never above the reservation), `kind:"settled"`, saved, logged. A receipt that fails a check: keep the worst case, `kind:"unknown"`, log which check failed; not closed. (Orchestrator clarification after review: if the entry's nonce is already used on chain (latest nonce > entry.nonce), close it once at worst case with `t = now()`, `closed:"receipt-rejected"`, like replaced-or-dropped; if unused, keep unknown/counted. A findByNonce replacement without a valid `tx.gasLimit` is rejected.)
3. No receipt: if `nonceUsed` the tx was replaced or dropped. Ask the injectable `deps.findByNonce(operator, nonce)` -> `{ receipt, tx } | null` (default returns `null`: standard JSON-RPC has no by-nonce lookup). A result is accepted under the checks of step 2 with the hash replaced by `tx.hash`, plus `tx.nonce == entry.nonce`, `tx.from == operator`, `gasUsed` within `[21000, tx.gasLimit]`; settle at that receipt (cost capped by the entry's reservation). Not found or not accepted: settle at the worst case ONCE: `kind:"settled"`, `wei` = worst case, `t = now()` (counts a further 24 h from the closing, then ages out), `closed:"replaced-or-dropped"`. Closed entries are never re-examined. If the nonce is NOT used the tx is pending: keep `reserved`, still counted at worst case, log `pending: nonce N not used yet`; this alone does not stop the run (see OPEN QUESTIONS).
4. Legacy entries (from f0c24ab and earlier: `reserved`/`unknown` with `tx:null` or without `nonce`) cannot be proven: close ONCE at worst case with `t = now()`, `kind:"settled"`, `closed:"legacy-unsettled"`. A legacy entry that has a hash but no nonce is first looked up by hash (steps 1-2); no receipt -> closed as legacy.
5. An RPC error for an entry (receipt or nonce read) leaves it unchanged and counted, is logged, and the run continues. A failed state save after a settlement stops the run (kept).
6. `spentWindowWei` counts `reserved` and `unknown` entries at any age; `serializeState` keeps both kinds at any age until settled (7-day pruning applies to `settled`). A crashed `reserved` entry is never silently aged out.
7. `simulate` mode never settles, saves, or makes these calls, but its cap decisions count those entries.

**L1-3 Strict validation on read (`logic.readState`).** Keep `{ok:false, kind:"corrupt", reason, file}`. In addition to `t`/`wei`: `kind` (if present) is `reserved|unknown|settled`; `tx` (if present, not null) matches `/^0x[0-9a-fA-F]{64}$/`; `nonce` (if present) is a non-negative safe integer; `gasLimit`, `maxFeePerGas`, `l1` (if present) are decimal strings `/^\d{1,40}$/`; `from`/`to` (if present) are valid addresses; `closed` (if present) is a string of at most 40 chars; unknown extra fields are ignored; entries with only `t` and `wei` stay valid. A violation gives a reason naming index and field (`gasSpends[3].nonce is not a non-negative integer`). The file is left untouched; collect mode sends nothing and logs `STATE UNREADABLE (<reason>)` (existing path). No stack is ever printed for bad state.

**L1-4 Exact manager.** `assertSignable(tx, lim, expect)` takes `expect.manager` (the position's allowlisted manager of the loop iteration) and requires `tx.to` equal to it (case-insensitive) in addition to being allowlisted; missing `expect.manager` -> refuse. `assertSignable` also requires `Number.isSafeInteger(tx.nonce) && tx.nonce >= 0`.

**L1-5 README** (that section only): replace every `2 x L1 fee quote` / `2 x L1 quote` used as a formula (worst case, settled amount, `maxGasPerTxEth` row) with `max(2 x L1 quote, minL1AllowanceEth)`; describe sign -> record (hash, nonce) -> broadcast; document the self-healing settlement (receipt validation, replaced/dropped by nonce, pending stays reserved, legacy and crashed `reserved` entries settled at run start, `reserved`/`unknown` never expire until settled, the one-time worst-case close with a fresh 24 h); delete the paragraph that tells the operator to edit `state.json` by hand (keep `--init-state`); state that a broadcast error or hashless response stops the run (exit 1) and is settled on the next run.

**Orchestrator clarification after security review:** in-run receipts are validated with `checkReceipt` before settling (a rejected one or `TRANSACTION_REPLACED` keeps the worst case as unknown and stops the run); each new entry records `maxPriorityFeePerGas` (optional on read) and a receipt price below it counts as `maxFeePerGas`; an entry older than 24 h settled at run start gets `t = now`; `checkReceipt` requires a positive safe-integer `blockNumber`.

## Design (implementer follows; deviations need the orchestrator)

**P1-A Routes (dispatch before the `?chain=` redirect).** `/portfolio` (also `/portfolio/`) -> HTML shell; `/api/aggregate` -> JSON; `/aggregate-view.js`, `/aggregate.css`. These ignore the `lpchain` cookie and `?chain=`; their own filters are `?chains=a,b` and `?wallet=<addr|label>` (client-side filtering of the full payload is the primary mechanism; the query params only preselect). `?refresh=1` on `/api/aggregate` bypasses the router cache TTL (still one in-flight round per chain; never passes `fresh=1` upstream; rate-limited to one forced round per chain per 5 s).

**P1-B Navigation.** `pickerHtml` gets a "Portfolio" anchor `href="/portfolio"` (no `data-chain`, so the existing click handler ignores it), visually distinct from the chain tabs and marked `aria-current="page"` on the portfolio page. The `/portfolio` page has its own bar: chain tabs there link to `/?chain=<key>` (which sets the cookie and lands on that chain's dashboard) and a "Dashboard" link to `/`. Every aggregated item links to `/?chain=<key>` (LP/token/staking rows alike); an unreachable chain's link still works (the router's existing 502 page appears).

**P1-C Per-chain fetch and states.** For each chain in `CHAINS`: four GETs in parallel. Chain `status`:
- `ok`: all four parts answered 200 within the timeout, source ages <= 15 min (the instance's own staleness rule for `/api/watch`), and no watched wallet row is `stale`/`ok:false`;
- `partial`: some parts failed or some wallet rows are stale/failed; items from the good parts are shown, each failed part and wallet is named in `problems[]` (`{part|wallet, code, since?}`);
- `stale`: nothing fresh, served from the router's last-good snapshot; `lastGoodAt` shown;
- `loading`: upstream answered 202/503 "still loading" (or the round has not finished) and there is no last-good;
- `down`: connection refused/timeout/garbage and no last-good.
Items from a last-good snapshot or from a wallet row with `stale:true` carry `stale:true` and `asOf` (ms). A chain listed in `CHAINS` but unreachable is always shown (banner), never silently omitted.

**P1-D Normalised item** (output `items[]`, one array, `kind` distinguishes): `{id, kind:"lp"|"token"|"staking", chain, wallet:{address (checksummed or as given), key (lowercase), label}, protocol:"uniswap-v3"|"uniswap-v4"|"aerodrome"|"pulsex-v2"|"other:<name>"|"token"|"staking", name (pair or symbol), valueUsd|null, feesUsd|null, rewardsUsd|null, rewardsCounted:boolean, rewardsReason|null ("unpriced"|"gauge-killed"|"duplicate"), counted:boolean, reason|null ("thin-pool"|"price-gap"|"unanchored"|"unpriced"|"decimals-unverified"|"duplicate-of-holdings"), flags:{thin, assumed, staked, killedGauge, feesUnavailable, stale}, inRange:boolean|null, amount|null, price|null, asOf, source:"positions"|"watch"|"portfolio"|"staking", link:"/?chain=<key>"}`. `rewardsUsd` is the pending reward of an `external` item's `rewards.usd` (null when absent/unpriced). Protocol mapping: `version 3` -> uniswap-v3, `version 4` -> uniswap-v4, `external` entries by `protocol` name (case-insensitive contains `aerodrome`/`slipstream` -> aerodrome, `pulsex` -> pulsex-v2, else `other:<name>`).

**P1-E Counting rules (identical to the instance where it has one; pending rewards are a deliberate user-decided difference, Q3).**
- LP counted iff `valueUsd != null && !thin && counted !== false`; otherwise it is listed with its `valueUsd` (if any) and `reason`, excluded from totals, and summed into `uncounted.usd` / `uncounted.count`. `valueUsd == null` is never treated as 0 anywhere: shown as "unpriced".
- Fees: counted only for counted LP items with `feesOk !== false` and `feesUsd != null`; `feesUsd == null` or `feesOk === false` shows "fees unavailable" (flag), not 0. (Deliberate difference: the instance's `totals.feesUsd` also adds the fees of uncounted pools; the aggregate does not. Document in the README.)
- Pending rewards (gauge/farm rewards such as AERO, and any other pending-reward USD an instance reports on an `external` item's `rewards`) ARE counted in the grand total and in `breakdown.byChain` / `byWallet` / `byProtocol` (attributed to the item's chain, wallet, protocol), AND shown as their own visible line `totals.rewardsUsd` (and per item `rewardsUsd`). A reward is counted iff `rewards.usd` is finite and >= 0 (not null), `rewards.killed` is not true and `gaugeKilled` is not true, and the reward is not a duplicate (P1-F rule 5). It is counted independently of whether the LP value itself is counted (a thin/price-gap LP still earns a priced, claimable reward; the LP value stays uncounted). Unpriced rewards (`usd` null) and killed-gauge rewards are NOT counted: they are listed as "not counted" with `rewardsReason` and summed into `totals.rewardsUncountedCount` (their USD, if any, into `totals.rewardsUncountedUsd`). Assumption: a killed gauge's reward is not claimable, hence excluded. Only `external` item `rewards` are pending rewards; the instance's `totals.rewardsUsd` is ignored in favour of per-item values, and sNET staking `rewards.*` (`today/d7/d30/total*`, already received into the balance) are NEVER pending rewards and never added (P1-F rule 3).
- Token rows: counted iff `usd != null` (price known, amount scaled). `unavailable`/`unscaled` or `price == null` -> uncounted with reason, amount shown if known. `thin` rows stay counted at the instance's already-capped `usd`, flagged. `assumed` rows stay counted and are summed into `totals.assumedUsd` (shown beside the total as "priced by assumption"). Rows with amount 0 or null-and-no-reason are dropped. A reward token that is also a wallet holding (e.g. AERO in the wallet) is a separate thing: held balance is a token row, pending reward is a reward; both count.
- Main wallet tokens come from `/api/portfolio` `rows[]` using `wallet` x `price` only (`walletUsd`, capped as the instance does); watched wallets from `holdings.tokens[]`. If `/api/portfolio` is down the main wallet's tokens are "unavailable" in `problems[]`, its LP still shows.
- **Grand total** `grandUsd = lpUsd + feesUsd + rewardsUsd + tokensUsd`, where `lpUsd` = sum of counted LP `valueUsd`, `feesUsd` = fees of counted LP items (rule above), `rewardsUsd` = counted pending rewards, `tokensUsd` = counted token value (staking is inside tokens, see dedupe; a `kind:"staking"` fallback item counts into `tokensUsd`). `uncounted` and `rewardsUncounted*` are reported separately; `incomplete:true` whenever any enabled chain is `down`/`loading`, or any part/wallet is missing, with the list. Stale last-good data (including its rewards) is included in the grand total, flagged, and ALSO summed separately as `totals.staleUsd` with the oldest `asOf`, named in the banner (decision Q1).

**P1-F No double counting (dedupe keys).**
1. LP item key = `chain | walletKey | protocol | (tokenId)`; the same key arriving from `/api/positions` and `/api/watch` (or twice in either) is kept once, preferring `/api/positions` for the main wallet; the main wallet address appearing in `/api/watch` is dropped from the watch side by address. A gauge-staked NFT (only in `external`) and an unstaked one never share a key (tokenId differs by `nftId`/`-farm-<pid>`); a v2 pair held unstaked and the same pair farm-staked are two items (different amounts).
2. Token key = `chain | walletKey | (address lowercase | "native")`. Main-wallet rows use only the wallet-held amount (never `pools`, `fees`, `total`, `usd` of `/api/portfolio`), so LP principal and uncollected fees are counted once, in the LP items. Defensive rule: a token row whose address equals the `poolAddress` / LP pair address of an LP item of the same chain+wallet is dropped as `duplicate-of-holdings` (LP token also listed as a holding). Native and its ERC-20 twin (Arc USDC) are one row (the instance already dedupes; the aggregate additionally drops a second row with the same key).
3. Staking: a staking token whose `token` address matches a token row of the same chain+wallet is NOT added again: the token row is tagged `flags.staking=true` and carries `stakingRewards:{d7Usd,d30Usd,totalUsd}`, `aprPct`. Only if there is no matching holdings row (holdings part failed) is the staking balance added as a counted `kind:"staking"` item, and then the holdings row, if it later appears, wins. Staking rewards figures are display-only history: they are never added to `rewardsUsd` or `grandUsd` (they are already inside the rebased balance).
4. The same address on several chains is ONE wallet in `wallets[]` and `breakdown.byWallet` (key = lowercase address), with `labels` per chain; display label = the first non-empty label in `CHAINS` order, aliases shown when others differ. Items of that wallet on different chains stay separate items (different chain).
5. Pending rewards are keyed with their item: reward key = the LP item key (rule 1) + `reward`. Because the reward belongs to the deduped item, the same pending reward reported by both `/api/positions` and `/api/watch` for the same position (or by both `positions[]`/`external[]` of one payload) is counted once; when the duplicate item is dropped its reward is dropped with it (preferring `/api/positions`). Two different positions of one wallet that each carry a reward are two rewards (both counted); a reward is never merged with a token row of the same symbol.

## Design (implementer follows; deviations need the orchestrator)
**D1 note.** In `compose()`, a wallet with `holdings.ok === false` produces `notes.push({wallet, code:"holdings-unavailable"})` instead of a problem. `compose()` returns `notes`; `build()` outputs `chains[].notes` (copy), `wallets[].notes` (codes for that wallet across chains) and `wallets[].holdingsUnknown:true`. Token items of that wallet get `flags.holdingsUnknown:true`. `incompleteList` and `status` ignore notes. `payload.incomplete` is unaffected by notes.
**D2 view.** A wallet with `holdingsUnknown` shows a badge "tokens unknown (discovery failed)" on its rows and in its breakdown row; its countedUsd is labelled "at least" (known tokens only). A chain with only notes shows no banner. Strings go through `esc()`.
**D3 L1.** `cached()` rebuilds (compose + build + stringify) when ANY of: the version changed (as today); `clock() - cache.builtAt >= buildMaxAgeMs` (option `buildMaxAgeMs`, default 1000, env `LP_AGG_BUILD_MS` in `chain-router.js`); `clock() >= cache.nextFlipAt`, where `nextFlipAt` is the smallest `part.at + SOURCE_STALE_MS + 1` above `now` over all usable parts (so the 15-minute stale flag flips exactly on time).
